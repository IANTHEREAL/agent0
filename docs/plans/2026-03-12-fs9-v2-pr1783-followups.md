# fs9 v2 (PR #1783) Follow-ups: CAS + Retry Hardening

Date: 2026-03-12

This note records the follow-up work done directly on the `fs9-v2` branch to address high-value
review findings around correctness under concurrency and long-lived uploads.

## Context

fs9 v2 relies on:

- TiKV as the authoritative metadata plane
- `_fs_L{inode}` lifecycle sidecar as the only durable transitional truth
- S3 as the data plane (objects + pack/bundles)

Long-lived uploads (`CreateUpload` + presigned multipart) require a CAS guard that detects races,
including in-place mutations where inode id stays stable.

## Changes Implemented

### 1. Upload CAS: add explicit inode generation

Problem: `expected_prior_inode` alone is not a safe "generation" token because many write paths
mutate content in-place without changing inode id.

Fix:

- Add `Inode.generation: u64` with `serde(default)` for mixed-version safety.
- Bump `generation` on any visible content mutation:
  - `write_file`
  - `write_file_at`
  - `truncate`
- On atomic publish (staging -> namespace), set the published inode's `generation` as:
  - `prior.generation + 1` when overwriting an existing file
  - `>= 1` for new files

Upload protocol changes:

- Add `expected_prior_generation` to:
  - `_fs_L` `UploadReservation`
  - HMAC `UploadTokenClaims`
- Enforce `expected_prior_generation` at publish time (only when present, to remain compatible
  with older tokens/reservations during rollout).

### 2. Superblock allocator conflicts: add bounded retries

Problem: `alloc_inode()` updates the superblock key and can conflict frequently under optimistic
transactions. Some public operations did not retry on commit conflicts.

Fix:

- Add bounded retry-with-backoff (using `FS9_TIKV_COMMIT_RETRY_ATTEMPTS`) for:
  - `begin_write_stream()` initial staging commit (object and legacy)
  - `create_upload()` reservation commit
- Ensure external side effects are cleaned on retry:
  - Abort multipart uploads on failed TiKV commits before retrying.

### 3. Parent namespace CAS: relax for missing parents

Problem: When `expected_parent_inode == None` (parents missing at reservation time), publish would
fail if someone created parent directories before `CompleteUpload`.

Fix:

- In `verify_upload_publish_preconditions()`, only require exact parent inode match when
  `expected_parent_inode` is `Some(_)`. If it is `None`, allow either:
  - still missing (publish will create parents), or
  - now existing as a directory path.

### 4. WS control-plane throughput: pipelining + batch inline reads

Problem: The WS server previously handled one JSON request at a time per connection
(`parse -> await handler -> respond`), which makes small-file workloads RTT-bound even with
`batch_write`. Additionally, the protocol had no read-path batch helper for tiny files.

Fix:

- Add a bounded `batch_inline_read` WS operation that returns per-path results with inline base64
  content (intentionally not streaming).
- Add per-connection WS request pipelining on the server:
  - the connection can accept multiple in-flight JSON operations concurrently
  - responses may return out-of-order (callers must match by `id`)
  - bounded by `FS9_WS_MAX_INFLIGHT_REQUESTS_PER_CONNECTION` (default 32)
  - permits are acquired before spawning work to avoid unbounded task buildup under spammy clients

New knobs:

- `FS9_WS_MAX_INFLIGHT_REQUESTS_PER_CONNECTION`
- `FS9_BATCH_INLINE_READ_MAX_FILES`
- `FS9_BATCH_INLINE_READ_MAX_FILE_BYTES` (defaults to `FS9_INLINE_MAX`)
- `FS9_BATCH_INLINE_READ_MAX_TOTAL_BYTES`

## Remaining High-Value Gaps (not implemented here)

- Legacy page deletion is still unbounded per txn (`delete_pages`): needs incremental deletion and
  a durable cursor/marker.
- Bundle compaction worker (rewrite live entries -> new bundle -> CAS update -> retire old bundle).
- Decide checksum contract (enforce on read vs metadata only).
- Server-mediated multipart streaming memory budget (global/per-tenant buffering limits).
